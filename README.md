# ごみくらべ

> 引っ越し先でも迷わずゴミを出せるようにするサービス

引っ越したばかりの人のためのスマートフォン向けWebアプリです。
前の街と新しい街（町名・丁目や地区まで）を選んで品目を入力するか、ごみの写真を撮ると、それぞれの街での分別区分・収集曜日・次回の収集日・注意事項を並べて表示します。

授業「開発プロジェクト演習」で制作しているプロトタイプです。

## 主な機能

### 実装済み

| 機能 | 内容 |
| --- | --- |
| 地域設定 | 今の街・前の街それぞれについて、自治体 → 町名・地区 → 丁目・区域を選ぶ（丁目がない地区は選択不要）。端末（localStorage）に保存し、次回も引き継ぐ |
| 品目検索・比較 | 品目名を入力すると、今の街と前の街での「分別区分」「収集曜日」「次回の収集日」「注意事項」を並べて表示。入力中は両方の自治体の品目から部分一致で候補を表示 |
| 似た品目 | 名前が完全に一致しない自治体では、表記の近い「似た品目」を提示。押すとその側の欄だけが切り替わるので、今の街と前の街で別々の品目を選んで比較できる（例：「食用油」と「油(食用の植物油)」） |
| 収集曜日の表示 | 選んだ地域の収集スケジュールから、その品目の収集曜日を表示。粗大ごみは「個別申し込み」、集団回収・拠点回収・施設への持ち込みの品目は「曜日収集なし」、自治体が収集しないものは「〇〇市（区・町）では収集しません」と表示。丁目より細かい例外（中野2・3・5丁目の毎日収集地域）は注意文を表示 |
| 次回収集日 | 収集曜日から次回の収集日（今日・明日・月/日）を表示。年末年始（12/29〜1/7、自治体によっては1月中）は日付を出さず自治体の案内を確認するよう表示。祝日も通常どおり収集する前提で計算 |
| 自治体比較一覧 | 今の街と前の街で分別区分が違う品目だけを一覧表示。品目名と「今の自治体の分別区分」で絞り込み、30件ずつ表示 |
| ごみ出しスケジュール | 選んだ地域の区分ごとの収集曜日と次回収集日、出す時間・祝日の扱いなどの案内、指定袋、粗大ごみの申込先（Web申込・電話）を表示 |
| 写真からごみ判定 | 写真を Gemini API で判定し、候補の品目と今の街・前の街の分別を表示。候補を選ぶと通常の検索結果を表示。ボタンは端末に合わせて出し分ける（Android は「撮影する」「写真を選ぶ」の2つ、iPhone・iPad は「撮影・写真を選ぶ」1つ、パソコンは「写真を選ぶ」1つ）。モデルが混雑・使用不可のときは自動で別のモデルに切り替え |
| データの出典 | 画面下の折りたたみの枠に、自治体ごとの出典と公式照合日を表示（設定中の自治体を先頭に表示） |

### データ形式

**品目データ**（`data/*_garbage_items.json`）

```json
{
  "city_code": "131121",
  "city_name": "世田谷区",
  "items": [
    { "id": "setagaya_0001", "name": "アイスピック", "category": "不燃ごみ", "note": "新聞紙等に包んで「キケン」と表示してください" }
  ]
}
```

**収集スケジュール**（`data/*_garbage_schedules.json`）

```json
[
  {
    "town": "赤堤",
    "blocks": [
      {
        "target_blocks": ["1", "3", "4", "5"],
        "schedule": { "burnable": "水曜日・土曜日", "non_burnable": "第2・第4月曜日", "resource": "木曜日", "bottle": "第1・第3月曜日" }
      }
    ]
  }
]
```

`schedule` のキー（`burnable` など）は自治体ごとに異なります。各自治体の分別区分とキーの対応は `src/config/municipalities.js` の `scheduleKeys` で設定しています。

| 自治体 | キー | 区分 |
| --- | --- | --- |
| 世田谷区 | `burnable` / `non_burnable` / `resource` / `bottle` | 可燃ごみ / 不燃ごみ / 資源 / ペットボトル |
| 中野区 | `burnable` / `glass_metal` / `resource` / `plastic` | 燃やすごみ / 陶器・ガラス・金属ごみ / **びん・缶・ペットボトル** / **資源プラスチック** |
| 毛呂山町 | `burnable` / `non_burnable` / `hazardous` / `plastic` / `bottle_can` / `pet` / `paper_cloth` | 燃やせるごみ / 燃やせないごみ / 有害ごみ / その他容器包装プラスチック / びん・かん類 / ペットボトル / 紙・布類 |
| 白岡市 | `burnable` / `non_burnable` / `glass` / `hazardous` / `pet_bottle` / `beverage_can` / `paper_cloth` | 燃えるごみ / 燃やせないごみ / ガラス類 / 有害ごみ / ペットボトル / 飲食料用缶 / 古紙・布類 |

収集日データを更新するときは、自治体の公式の収集日一覧と照合してください（中野区は `resource` と `plastic` を取り違えやすいので注意）。

### 自治体を追加するには

コードの変更は不要です。データと設定を追加するだけで、品目検索・比較一覧・収集日・写真判定のすべてで使えるようになります。

1. `data/` に `〇〇_garbage_items.json`（品目と分別区分）と `〇〇_garbage_schedules.json`（町名・丁目ごとの収集曜日）を、上の「データ形式」に合わせて追加する
2. `src/config/municipalities.js` の `MUNICIPALITY_CONFIG` に、その街の設定を1つ追加する（既存の自治体の設定をコピーして書き換える）

    | 項目 | 内容 |
    | --- | --- |
    | `name` | 画面に表示する自治体名（例：中野区、〇〇市、毛呂山町） |
    | `itemsUrl` / `schedulesUrl` | 1 で追加したデータのパス |
    | `scheduleKeys` | 分別区分ID（ファイル冒頭の説明を参照）→ 収集日データの項目名 |
    | `scheduleRows` | 「ごみ出しスケジュール」タブに表示する行と、その表示名 |
    | `designatedBag` | 指定袋の案内 |
    | `oversizedApplicationUrl` / `oversizedApplicationLabel` | 粗大ごみのWeb申込ページとボタンの文言 |
    | `oversizedApplicationTel` / `oversizedApplicationTelLabel` | 粗大ごみの申込電話番号とボタンの文言（電話申込の自治体。Webと両方でも可） |
    | `oversizedDetailsUrl` / `oversizedDetailsLabel` | 粗大ごみ案内ページと、リンクの文言（省略時は「〇〇公式の粗大ごみ案内」） |
    | `scheduleNotes` | 朝何時までに出すか・祝日の扱いなど（公式で確認できた内容だけ） |
    | `yearEndUntilJanuary` | 1月に収集日がずれる自治体は、1月の何日まで次回収集日を出さないか（省略時は1/7まで） |
    | `nonRegularGuides` | 集団回収（`collective`）・拠点回収（`drop_off`）・施設への持ち込み（`self_carry`）の品目に出す案内文 |
    | `sources` / `verifiedOn` | データの出典（資料名とURL）と、収集日データを公式と照合した日。画面下の「データの出典」に自動で表示される |
    | `areaNotices` など | 必要な場合だけ（丁目より細かい例外、集団回収の案内、表示名の上書きなど） |

3. （任意）名前が違う同じ品目があれば、`ITEM_ALIASES` に追加する。名前が同じ品目や、括弧を除くと同じになる品目は自動で照合されるので不要
4. 収集日データを、自治体の公式の収集日一覧と照合する

**注意**

- 次回収集日は「祝日も通常どおり収集する」前提で計算します。祝日に収集しない自治体を追加する場合は、`scheduleNotes` にその旨を書いてください
- 町名ではなく地区（例：毛呂山町のA・B・C地区）で収集日が決まる自治体は、`town` に地区名を入れ、`target_blocks` を空にします（丁目の選択は不要になります）
- 丁目以外の区域で分かれる場合（例：白岡市の「宇都宮線東側」）は、`target_blocks` にその区域名を入れます。同じ町名を複数の行に分けて書いてもかまいません（画面では1つにまとまります）
- 収集曜日は「月曜日・木曜日」「月・木」「第1・第3金曜日」「第1・3金曜日」「第1金曜日」のどの書き方でも読めます
- 分別区分の名前は「燃える／可燃」「不燃／燃えない」「資源」「プラ」「粗大」「有害」「〇〇では収集できない」などの一般的な言葉なら自動で判定されます。独特な名前の場合は、追加後に全品目の判定結果を確認してください

写真判定では、Gemini に「今の街」の品目一覧から品目を選ばせ、「前の街」の同じ品目を自動で照合して並べて表示します。

## 開発環境の準備

1. リポジトリをクローンする

    ```sh
    git clone （リポジトリのURL）
    cd gomikurabe
    ```

2. 必要なパッケージを入れ、設定ファイルを作る

    ```sh
    npm install
    cp .env.example .env   # .env の GEMINI_API_KEY に自分のAPIキーを書く
    ```

3. サーバーを起動する（写真判定にはこのサーバーが必要です）

    ```sh
    node server.js
    ```

4. ブラウザで <http://localhost:3000> を開く

> `python3 -m http.server` で開いた場合や `index.html` を直接開いた場合は、写真判定が動きません（品目検索・収集日は `python3 -m http.server` でも動きます）。

### 写真判定（Gemini）の設定

| 項目 | 内容 |
| --- | --- |
| `GEMINI_MODEL` | 使うモデル（初期値 `gemini-3.5-flash`）。`gemini-2.5-flash` は新しいAPIキーでは使えません。上位の 3.8 / 3.7 は混雑しやすいため、安定して応答する 3.5-flash を基本にしています |
| `GEMINI_FALLBACK_MODELS` | 設定したモデルが混雑・上限・使用不可のときに順に試すモデル（カンマ区切り、初期値 `gemini-3.8-flash,gemini-3.7-flash,gemini-3.5-flash-lite`） |
| 待ち時間 | 1モデル20秒・全体40秒（サーバー）、50秒（ブラウザ）で打ち切り、「少し待ってから再度お試しください」と表示 |
| 利用回数 | 同じ利用者（IPアドレス）から10分あたり20回まで（`RATE_LIMIT_MAX` で変更可） |
| 判定結果の保存 | 同じ写真をもう一度送ったときは Gemini を呼ばずに前回の結果を返す（`results_cache.json`。画像の中身から計算したキーで保存し、画像そのものは保存しない） |

スマートフォンで試すときは、パソコンとスマートフォンを同じ Wi-Fi につなぎ、スマートフォンで `http://（パソコンのIPアドレス）:3000` を開く（IPアドレスは `ipconfig getifaddr en0` で確認）。

## 公開（Render）

1. [Render](https://render.com/) に GitHub アカウントでログインし、「New」→「Web Service」でこのリポジトリを選ぶ
2. 次のように設定する

    | 項目 | 設定 |
    | --- | --- |
    | Branch | `main` |
    | Build Command | `npm install` |
    | Start Command | `npm start`（`node server.js` と同じ） |
    | Instance Type | Free |

3. 「Environment Variables」に次を登録する（`.env` はアップロードしない）

    | Key | Value |
    | --- | --- |
    | `GEMINI_API_KEY` | 公開用に新しく作ったAPIキー |
    | `GEMINI_MODEL` | `gemini-3.5-flash` |

4. デプロイが終わると `https://〇〇.onrender.com` のURLが発行される

**注意**

- 無料プランは15分アクセスがないと停止し、次に開いたときに起動まで1分ほどかかる。発表やデモの前に一度開いておく
- 再起動すると判定結果の保存（`results_cache.json`）は消える（自動で作り直される）
- 写真判定は、同じ利用者（IPアドレス）から10分あたり20回まで（`RATE_LIMIT_MAX` で変更可）
- ブラウザに公開されるのは画面に必要なファイル（`index.html`・CSS・JS・`src/`・`data/`）だけ。`server.js` や `.env` などは公開されない

## ⚠️ 注意（チーム全員へ）

- **APIキーを絶対にコミットしない**。`.env.example` をコピーして `.env` を作り（`cp .env.example .env`）、そこにキーを書く。`.env` と `node_modules/` は `.gitignore` で除外済み
- `node_modules/` はコミットしない。クローン後に `npm install` で作成する
- 本番のAPIキーは、公開先サービスの管理画面の「環境変数」に登録する（コードや GitHub には書かない）
- 写真は判定にのみ使用し、アプリ側では保存しない（判定のため Google の Gemini API に送信される。画面にもその旨を表示）
- 作業を始める前に必ず `git pull` する（古いファイルのまま作業すると、ほかの人の修正が戻ってしまう）
